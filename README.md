# HERD International — Research Data Portal & Centre for Data Science Hub

Official public portal for **HERD International's Centre for Data Science**:  
🔗 **Live Portal:** [https://herd-data-portal.github.io/herd-data-portal/](https://herd-data-portal.github.io/herd-data-portal/)

This portal provides a searchable, structured, zero-cost research data catalogue, a Data Science/ML/AI learning hub for students and researchers, and public health data standards—while keeping sensitive or participant-level datasets strictly private inside HERD's institutional storage.

---

## Portal Overview (3 Tabs)

| Tab | File | Purpose |
| :--- | :--- | :--- |
| **Data Catalogue** | `index.html` | Browse approved projects by year, thematic area, resource type, and search terms; explore HERD's 6-folder + subfolder structure; download public Zenodo files or submit access requests. |
| **DS & AI Hub** | `learn.html` | 6-pillar curriculum covering Data Engineering, Survey Statistics, Machine Learning & SHAP, GIS, Private Local AI/RAG, and Ethics—plus a side-by-side **Stata / R / Python Code Lab** and open-source software links. |
| **Standards & Impact** | `standards.html` | Curated Nepal & Global Open Health Data directory, HERD data quality/de-identification/citation standards, downloadable codebook template, **synthetic practice CSV datasets**, and student/collaborator pathways. |

## Architecture & Data Governance

To stay **$0/month**, scalable beyond GitHub's 1 GB limit, and compliant with research ethics, the portal decouples the **catalogue interface**, **public archives**, and **restricted datasets**:

1. **Catalogue Frontend (`GitHub Pages` + `GitHub Actions`):** Hosts only lightweight HTML, CSS, JavaScript, and JSON metadata.
2. **Public Files (`Zenodo`):** Approved public outputs (`.pdf`, `.docx`, `.do`, `.ipynb`, `.png`, clean summary `.csv`) are archived on Zenodo (up to 50 GB per record with versioning and citable DOIs) and linked into the portal.
3. **Restricted / Private Files (`Microsoft OneDrive / SharePoint` + `Microsoft Forms`):** Unreleased, de-identified request-only, or sensitive datasets never leave HERD's Microsoft 365 environment. Clicking **Request** routes visitors to HERD's access request form for project-owner review.
4. **No-Code Content Management (`Pages CMS`):** Team members can add, edit, or remove project listings via forms and dropdowns at [`app.pagescms.org`](https://app.pagescms.org/) without editing code manually.

## How to Add or Update a Project (Recommended CMS Workflow)

### Option A: Using Pages CMS (No Coding Required)
1. Sign in to [`app.pagescms.org`](https://app.pagescms.org/) and open the **`herd-data-portal`** repository.
2. *(For public files)* Upload approved public files to **Zenodo** first, publish the record, and copy the clean public `/files/...` or DOI URL.
3. Go to **Research Projects → Add an entry** (or click **Edit** on an existing project):
   * Enter **Project Year**, **Project Short Title**, **OneDrive Folder Code** (`PROJECTCODE_YEAR`, e.g., `CHORUS_2020`), **Thematic Areas**, and **Project Summary**.
   * Under **Approved Files & Datasets**, select the **Main Folder**, optional **Subfolder**, **File Format**, and **Access Level**:
     * `public` → paste the published Zenodo URL in **Zenodo Public URL**.
     * `request` → leave **Zenodo Public URL** empty.
4. Click **Save**.
5. **Automatic Build & Deploy:** GitHub Actions (`.github/workflows/build-catalog.yml`) runs `scripts/build_catalog.py`, updates `catalog.js`, and deploys the updated site to GitHub Pages within ~30–60 seconds.

### Option B: Local Python Build (For Developers)
If editing JSON files locally under `data/projects/`:

```bash
python scripts/build_catalog.py
```

## Standard Folder & File Naming Conventions

### 1. Project Folder Hierarchy
Every project follows HERD's standard 6-folder structure:
1. **Data Collection Tools** (`Qualitative Tools`, `Quantitative Tools`)
2. **Datasets** (`Final datasets`, `GPS data`, `Qualitative data`, `Raw datasets`, `Syntax`, `Urban Health Equity Data`)
3. **Field Manual**
4. **Others**
5. **Publications**
6. **Report**

*(Empty subfolders are hidden automatically on the public UI until an approved file is listed inside them.)*

### 2. Zenodo File Naming Standard
Files uploaded to Zenodo use lowercase, underscores between metadata segments, hyphens within titles, and a version suffix:

```text
<project>_<year>_<category>_<short-title>_<version>.<ext>
```

**Examples:**
* `r4r_2020_tool-quant_community-mapping-questionnaire_v1.0.pdf`
* `chorus_2020_report_final-summary_v1.0.pdf`
* `chorus_2020_syntax_equity-regression_v1.0.do`
* `chorus_2020_syntax_spatial-mapping_v1.0.ipynb`
* `chorus_2020_fig_budhanilkantha-ward-map_v1.0.png`

## Security & Data Ethics Rules

* **Never commit raw datasets, participant PII, or GPS coordinates** to this repository.
* **Never commit Zenodo draft/secret share URLs** containing `?token=...` into `data/projects/*.json` or `catalog.js`.
* **Never edit `catalog.js` directly** once Pages CMS / GitHub Actions is active—always update via Pages CMS or `data/projects/*.json`.
* Always inspect `.ipynb` cell outputs and `.do` file paths before publishing code publicly on Zenodo.
